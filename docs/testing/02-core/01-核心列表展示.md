## [P1] 验证 Windows GUI PATH 过期时仍识别 npm link 的本地核心
[测试类型] 功能
[前置条件] Windows 用户全局 npm prefix 为 `%APPDATA%\npm`；`@deepseek-ai/dsh` 通过 `npm link` 指向一个已构建 checkout；以不含该 prefix 的 PATH 启动桌面端。
[测试步骤] 1. 完整退出并重新启动桌面端。2. 打开「核心」面板。3. 检查本地行的版本、入口与选中态。4. 启动 Harness 服务并检查 desktop.log。
[预期结果] 1. 即使进程 PATH 不含 npm prefix，桌面端仍补扫 `%APPDATA%\npm`。2. 本地行 present=true，入口为 canonicalize 后的 checkout `apps\cli\lib\bin.js`，不是 junction 表面路径。3. active_core 未显式选择 app 时，本地行 active=true。4. 日志包含 `source=local` 和相同的真实入口。

## [P1] 验证启用 loopback token 认证的新核心可完成 Desktop 握手
[测试类型] 功能 / 安全
[前置条件] 活动核心启动后输出 `dsh web: http://127.0.0.1:<port>/?token=<token>`，匿名访问 `/` 与插件 bundle 返回 401。
[测试步骤] 1. 由 Desktop 启动核心。2. 等待核心输出认证 URL。3. 检查 Desktop 健康状态与 iframe。4. 匿名请求 loopback API。5. 检查服务日志与运行日志。6. 停止监听端口但暂不结束 Node 进程，再执行健康检查。
[预期结果] 1. Desktop 捕获一次性 URL 后，通过真实 HTTP 请求确认端口仍可达，并进入 ready，不会永久停在「Waiting for Harness」。2. Rust 宿主用 token 完成 303 交换，将 HttpOnly cookie 注入 WebView；token 不跨 IPC，iframe 只加载无 token 的普通服务地址并正常展示。3. 匿名 loopback API 仍返回 401，Desktop 不修改或绕过核心认证实现。4. 日志中的 token 被替换为 `<redacted>`。5. 端口停止监听后健康检查失败，不会仅凭缓存状态误报健康。6. 不输出认证 URL 的旧核心仍按插件 bundle 探测流程正常启动。
